# Проверка интеграции в живом Home Assistant

Чек-лист ручной проверки перед релизом. Заполняется один раз на релиз, результат — в заметках к
релизу или в PR.

## 1. Установка

```bash
cd /tmp
curl -L -o ha-mtdx62.tar.gz \
  https://github.com/sergeyastakhov/ha-mtdx62/archive/refs/tags/v0.1.0.tar.gz
tar xzf ha-mtdx62.tar.gz
mkdir -p /config/custom_components
rm -rf /config/custom_components/mtdx62
cp -r ha-mtdx62-0.1.0/custom_components/mtdx62 /config/custom_components/mtdx62
```

Затем перезапустить Home Assistant. Библиотеку `mtdx62-modbus-library==0.3.0` Home Assistant
поставит сам из PyPI при первом обращении к интеграции — она указана в `requirements` манифеста.

Нужен Home Assistant 2026.10 или новее.

## 2. Добавление датчика

Адаптер USB-RS485 подключить к хосту с Home Assistant. Настройки → Устройства и службы →
Добавить интеграцию → «MTDx62 Presence Sensor» → «Последовательный порт».

- порт: путь из `/dev/serial/by-id/…`, а не `/dev/ttyUSB0` — имя `ttyUSB0` меняется от
  переподключения к переподключению;
- скорость 9600, чётность «Нет», стоп-биты 1, адрес на шине 1;
- модель MTD262-MB (24 ГГц) или MTD062-MB (5.8 ГГц) — по наклейке.

Мастер проверяет связь до создания записи: если датчик не отвечает, форма останется открытой
с ошибкой «не удалось подключиться», и записи не появится.

## 3. Что проверить

| Что | Ожидание |
|---|---|
| Карточка устройства | производитель «Zhejiang Oujue Electronic Technology», выбранная модель, версия приложения 1.1.3 |
| Бинарный датчик присутствия | включается при движении, гаснет после задержки ухода (на стенде 15 с) |
| Освещённость | около 1740 лк при комнатном свете |
| Расстояние | выключено по умолчанию; после включения — около 1.1 м |
| Датчик состояния | выключен по умолчанию; после включения показывает «работает» |
| Версии прошивок | приложение `1.1.3`, радар `0.0.0` — так и должно быть |
| Диагностика | путь к порту заменён на `**REDACTED**`, сырые регистры и параметры на месте |
| Переконфигурация | смена адреса на шине сохраняет запись и сущности |
| Обрыв шины | выдернуть A/B: через ~15 с сущности становятся «недоступно», после возврата восстанавливаются сами |

Ремонт «зависла самопроверка» на здоровом датчике не проверить: код 0 держится меньше секунды,
а порог — 60 секунд. Для проверки нужен датчик, который действительно висит в самопроверке.

## 4. Что прислать

- версию Home Assistant;
- скриншоты карточки устройства и сущностей;
- файл диагностики (скачивается из меню записи, секреты уже вырезаны);
- всё, что попало в `Settings → System → Logs` с упоминанием `mtdx62`.

## 5. Проведённые проверки

**25.11.2026, Home Assistant 2026.11.3, MTD262-MB, Raspberry Pi, `/dev/ttyAMA4`.**

Подтверждено на живом устройстве:

- карточка устройства: производитель «Zhejiang Oujue Electronic Technology», выбранная модель,
  версия приложения `1.1.3`;
- сущности присутствия и освещённости показывают живые значения, расстояние около 1.1 м после
  включения, датчик состояния показывает «работает»;
- версии прошивок: приложение `1.1.3`, радар `0.0.0`;
- диагностика: путь к порту заменён на `**REDACTED**`, сырые регистры и параметры на месте;
- переконфигурация на занятый порт даёт осмысленную ошибку, а не молчаливый отказ;
- сообщения об ошибках читаемы и с подстановками — после очистки кеша браузера (см. раздел
  «Устранение неполадок» в README).

Не проверялось на живом устройстве:

- ремонт «зависла самопроверка» — нужен датчик, который действительно висит в самопроверке;
- работа через Modbus TCP-шлюз;
- две модели одновременно на одной шине.
