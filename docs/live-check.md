# Проверка интеграции в живом Home Assistant

Чек-лист на выпуск: что проверить руками, когда выходит новая версия. Записи о прошлых проверках
здесь не хранятся — они уходят в заметки релиза, чтобы этот файл оставался списком дел, а не
архивом.

## 1. Установка и обновление

Через Marketplace, без командной строки:

1. **Настройки → Устройства и службы → Добавить интеграцию → Marketplace**.
2. Добавить репозиторий `https://github.com/sergeyastakhov/ha-mtdx62` и установить
   **MTDx62 Presence Sensor**.
3. Перезапустить Home Assistant. Обновление — тот же экран: Marketplace сам предложит новую версию.

Библиотеку `mtdx62-modbus-library` Home Assistant поставит из PyPI сам: версия указана в
`requirements` манифеста. Нужен Home Assistant 2026.10 или новее.

Если Marketplace ещё не знает репозиторий (каталог не пройден), интеграция ставится как
пользовательский компонент — но это обходной путь, а не нормальный порядок.

## 2. Что проверить при выпуске

Отмечать только то, что затронуто релизом; остальное достаточно проверить один раз при добавлении
устройства.

### Устройство и сущности

| Что | Ожидание |
|---|---|
| Карточка устройства | производитель «Zhejiang Oujue Electronic Technology», выбранная модель, версия приложения |
| Присутствие | включается при движении, гаснет после задержки ухода, выставленной на датчике |
| Освещённость | правдоподобное значение в люксах с десятыми, не «сырое» число регистра |
| Расстояние | выключено по умолчанию; после включения — в метрах |
| Датчик состояния | выключен по умолчанию; после включения показывает «работает» |
| Диагностика | путь к порту заменён на `**REDACTED**`, сырые регистры и параметры на месте, версии прошивок видны |

### Настройки

| Что | Ожидание |
|---|---|
| Восемь чисел на устройстве | дальность, ближняя граница, отступ зоны, задержки, обе чувствительности, порог освещённости |
| Изменение дальности | значение уходит в датчик, сущность показывает подтверждённое число |
| Правило зон | попытка сделать `граница + отступ` больше дальности отклоняется с понятным сообщением |
| Зажатие | значение ниже предела (дальность 0.8 м, граница 0.1 м) отклоняется, а не подменяется датчиком |
| Параметры шины | по умолчанию сущностей адреса, скорости и чётности нет |
| Включение опции | флажок показывает предупреждение, второй шаг требует подтверждения |
| Смена адреса | после записи появляется ремонт «связь потеряна», сущности становятся недоступны |
| Возврат связи | переконфигурация записи с новым адресом возвращает устройство |
| Чтение пультом | изменение настройки ИК-пультом появляется в Home Assistant в течение минуты |
| Скрытые настройки | в блоке настроек пусто, пока не включить нужную сущность |
| Включённая настройка | после включения появляется число, запись применяется сразу |
| Параметры шины | в блоке настроек их нет; в диалоге «Настроить» три поля с текущими значениями |
| Код MAC | сущность выключена по умолчанию, после включения показывает код, есть в диагностике |

### Ошибки и сообщения

| Что | Ожидание |
|---|---|
| Тексты ошибок | читаемые, по-русски, с подстановками; после обновления — жёсткая перезагрузка страницы, иначе виден ключ вместо текста |
| Занятый порт | сообщение называет, кто держит порт: запись `modbus` из `configuration.yaml` или другое имя того же устройства |
| Переконфигурация | смена адреса на шине сохраняет запись, историю и идентификаторы сущностей |
| Обрыв шины | через ~15 с сущности становятся «недоступно», после возврата восстанавливаются сами |

### Что проверить нельзя

Эти пункты остаются вне проверки, пока нет подходящего стенда; в заметках релиза они
перечисляются как непроверенные:

- ремонт «зависла самопроверка» — нужен датчик, который действительно висит в самопроверке;
- работа через Modbus TCP-шлюз;
- две модели одновременно на одной шине;
- влияние порога освещённости на регистр присутствия — нужен стенд с гарантированным присутствием.

## 3. Как записать результат

В заметки релиза добавить строку: дата, версия Home Assistant, модель датчика, что проверено и что
осталось непроверенным. Всё, что не проверялось, называется прямо — иначе следующая проверка
начнётся с ложного «всё работает».

Если что-то не сошлось, к записи приложить:

- версию Home Assistant и интеграции;
- скриншоты карточки устройства и сущностей;
- файл диагностики из меню записи — секреты в нём уже вырезаны;
- всё, что попало в **Настройки → Система → Журнал** с упоминанием `mtdx62`.
