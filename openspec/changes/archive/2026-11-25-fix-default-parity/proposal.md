# Proposal

## Why

Мастер настройки предлагал нечётность как заводское значение. Это неверно: в сканах протокола
код чётности `0` означает «нет чётности», и живой датчик отвечает именно так — регистр `0x0009`
равен `0`, связь идёт на 9600 8N1. Пользователь, оставивший поля как есть, получал форму с
неверной чётностью и ошибку связи на первом же шаге.

Интеграция обещает в требовании, что значения по умолчанию совпадают с заводскими. Обещание
нарушено в одном поле, поэтому исправление — не только в коде, но и в требовании: сценарий на
чётность отсутствовал, и ошибка прошла незамеченной.

## What Changes

- `DEFAULT_PARITY` становится `"N"` вместо `"O"`.
- Значение по умолчанию для стоп-битов приводится к строке: селектор возвращает строку, а
  `probatio` проверяет и значение по умолчанию тоже, поэтому `1` как число отвергалось на
  валидации. В записи остаётся число.
- В требование «Значения по умолчанию для параметров связи» добавляется сценарий про чётность и
  стоп-биты, чтобы поле больше не осталось без проверки.
- Тест последовательного порта отправляет только обязательные поля и проверяет, что запись
  получила `9600`, `"N"` и `1` — то есть проверяет именно умолчания, а не то, что тест сам ввёл.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `mtdx62-connection`: уточняется сценарий умолчаний для последовательного порта.

## Impact

- Пользователи, которые добавляли датчик с нечётностью, ничего не теряют: их записи хранят
  прежние значения, переконфигурация не запускается.
- Новые записи создаются с корректной чётностью.
- Сквозные требования не затрагиваются: `conventions/modbus-transport` говорит о владении
  транспортом, а не о значениях полей.
