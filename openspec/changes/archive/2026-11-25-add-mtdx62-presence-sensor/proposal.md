# Proposal

## Why

Датчики присутствия MTD062-MB (5.8 ГГц) и MTD262-MB (24 ГГц) умеют отличать неподвижного
человека от пустой комнаты по дыханию и микродвижениям, но Home Assistant их не знает: у
устройств есть шина RS485 с протоколом Modbus, а готовой интеграции нет. Без неё датчик
бесполезен для автоматизаций — его единственный выход либо сухой контакт, либо регистры,
которые никто не читает.

Протокол описан производителем полностью (карта регистров, функции, примеры кадров), документация
собрана в `references/mtdx62/`. Разбор регистров выносится в библиотеку `mtdx62` — отдельное
изменение в `libraries/mtdx62-modbus-library/openspec/changes/add-mtdx62-device-library`. Здесь описана только
интеграция: связь с Home Assistant, сущности и диагностика.

## What Changes

- Появляется интеграция `mtdx62` для датчиков присутствия MTD062-MB и MTD262-MB по Modbus.
- **Одна запись конфигурации — один датчик.** Пользователь заполняет параметры связи (Modbus TCP
  через шлюз либо последовательный порт) и адрес датчика на шине; получается одно устройство
  Home Assistant. Несколько датчиков на одной шине — это несколько записей, и они делят одно
  соединение.
- Соединение не открывается самой интеграцией. Транспортом владеет интеграция `modbus` —
  требование `conventions/modbus-transport`. Наша интеграция просит юнит в `async_setup_entry`
  и проверяет связь в мастере.
- Для каждого датчика появляются сущности:
  - бинарный датчик присутствия (`occupancy`) — главная сущность;
  - датчик освещённости в люксах;
  - датчик расстояния в сантиметрах (по умолчанию выключен);
  - диагностические сущности: код состояния устройства, версия приложения и радара.
- Интеграция опрашивает датчик раз в 5 секунд и корректно переживает пропадание связи: сущности
  становятся `unavailable`, в лог пишется одна запись о потере и одна о восстановлении.
  Запись при обрыве не перезагружается — переподключение выполняет общий транспорт.
- Добавляется скачивание диагностики с вырезанными секретами (путь к последовательному порту,
  код MAC) — требование `conventions/diagnostics`.
- Первая версия **не пишет** параметры датчика (чувствительность, дальность, задержки, порог
  освещённости). Чтение и запись параметров — отдельное изменение: см. «Что отложено».

### Что отложено и почему

| Отложено | Причина |
|---|---|
| Запись параметров датчика (чувствительность, дальность, задержки, порог освещённости) | Требует модели сущностей `number`/`select` с ограничениями и шагом, проверки на живом устройстве и отдельного набора сценариев. Смешивать с первым выпуском — значит удвоить объём проверок до первого полезного результата. |
| Активный отчёт устройства (push) вместо опроса | Документация не описывает поведение при переполнении и потерю кадров; выигрыш по задержке при опросе раз в 5 секунд незначителен. |
| Repair issues для неисправностей радара | Неисправность железа пользователь не может устранить из интерфейса; достаточно диагностической сущности и записи в логе. |
| Автообнаружение (zeroconf/DHCP/USB) | Устройство — пассивный Modbus-слейв за шиной или шлюзом, само о себе не объявляет. |

## Capabilities

### New Capabilities

- `mtdx62-connection`: настройка связи с одним датчиком, проверка связи в мастере, изменение
  параметров, поведение при недоступности, выгрузка записи.
- `mtdx62-presence`: сущность присутствия человека и её доступность — то, ради чего интеграция
  существует.
- `mtdx62-environment`: освещённость и расстояние до цели как сопутствующие измерения.
- `mtdx62-device-health`: состояние устройства, версии прошивок и диагностика для разбора проблем.

### Modified Capabilities

Нет: `openspec/specs/` этой интеграции пока пуст.

## Impact

- **Новый репозиторий** `integrations/mtdx62` (custom-компонент `custom_components/mtdx62`,
  отдельный репозиторий GitHub для Marketplace).
- **Зависимости интеграции**: `mtdx62-modbus-library==0.3.0` — библиотека протокола из изменения
  `add-mtdx62-device-library`. Транспорт приходит из `modbus-connection` через неё.
- **Манифест**: `dependencies: ["modbus"]`, `connectivity: ["modbus"]`, `integration_type: device`,
  `iot_class: local_polling`, `loggers`: `mtdx62`, `modbus_connection`, `tmodbus`.
- **Оборудование**: датчики в исполнении RS485 через USB-RS485 адаптер либо TCP-шлюз.
- **Сквозные требования**, на которые опирается изменение: `conventions/modbus-transport`,
  `conventions/entity-availability`, `conventions/entity-identity`, `conventions/diagnostics`,
  `conventions/localization`.
- **Quality Scale**: изменение закрывает правила Bronze (`config-flow`,
  `config-flow-test-coverage`, `test-before-configure`, `test-before-setup`, `unique-config-entry`,
  `entity-unique-id`, `has-entity-name`, `runtime-data`, `appropriate-polling`, `common-modules`,
  `dependency-transparency`, `brands`, `docs-*`) и часть Silver (`config-entry-unloading`,
  `entity-unavailable`, `log-when-unavailable`, `parallel-updates`, `test-coverage`).
  Достижимый tier после этого изменения — **Bronze**, с прицелом на Silver в следующем изменении.
- **Домен**: `mtdx62`. Не совпадает ни с одним доменом Core; проверено — `home-assistant.io/integrations/mtdx62`
  отдаёт 404.
